What this PoC is arguing for

The Senior Cloud Architect role at Ambu calls for Azure depth, IaC, and GDPR / NIS2 / GxP. The missing piece is an autonomous platform: product teams request outcomes, the control plane converges continuously.

Kubernetes-native

Clusters, identities, and this app are Kubernetes APIs. Platform and product teams share one language — not a mix of portal clicks, Bicep modules, and ad-hoc scripts.

GitOps

Desired state lives in Git. Argo CD continuously reconciles. Drift is an event, not a surprise. The PR is the change-control record (GxP-shaped audit trail).

Control planes

Crossplane compositions turn “I need EndoIntelligence in prod” into ARM calls. Engineers file a claim; they do not become Azure specialists to ship a namespace.

Autonomous infrastructure

Self-heal in dev, tighter promotion in prod. The platform runs toward Git, 24/7 — the operating model of an Autonomous Infrastructure Platform, not a ticket queue.

Cloud-agnostic core

Azure is 99% of Ambu’s estate today — this cluster is AKS, Entra Workload Identity, North Europe. The interface is Kubernetes. Compositions can grow AWS/GCP providers without rewriting product repos.

No vendor lock-in via Bicep

Bicep/ARM describe Azure well and stay useful at the landing-zone edge. Binding every product pipeline to Bicep couples teams to one DSL. Git + Crossplane keeps Azure as a provider, not as the programming model.

Control plane on this cluster

AKS

Runtime in northeurope. OIDC issuer, Workload Identity, Azure CNI Overlay. EU data residency for a Danish manufacturer.

Crossplane

XRDs AmbuPlatform and EndoIntelligence. Claims, not tickets. ARM is still what Azure sees — Git is what humans review.

Argo CD

App-of-Apps: platform vs products. Same GitOps path a Cloud Engineer would operate day-to-day next to the architect.

Azure-first, not Azure-only

Ambu’s job description lists Terraform, Bicep, and ARM. This PoC does not discard them. It puts a Kubernetes control plane in front of Azure so the estate can stay Azure-centric without teaching every product team Bicep.

  1. Landing zones and hub networking can remain Terraform or Bicep — that is the architect’s blueprint.
  2. The inner loop (identities, namespaces, this portal) is claimed and reconciled from Git.
  3. If ZOOM AHEAD lands a workload on another cloud, the GitOps contract does not change; the provider does.

From pull request to North Europe

  1. Change the app or a Crossplane claim in Git.
  2. Review maps to change control — who approved what, when.
  3. Merge. Argo CD syncs. Crossplane talks to Azure Resource Manager if the claim changed.
  4. This Nginx front door is the product surface: no patient data, architecture only.
